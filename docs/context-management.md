# 上下文管理与调用观测

设计原则：减少无效上下文，但不以长度预算删除决策依据。模型工作上下文不是项目数据库；省略正文不等于省略事实，也不等于证据已经通过审核。

## 借鉴 Codex 的部分

Codex 官方配置公开了独立的 `model_auto_compact_token_limit`，并以 `tool_output_token_limit` 控制单个工具输出进入历史的预算。两类预算分别治理累计历史和新增内容。[官方配置](https://learn.chatgpt.com/docs/config-file/config-reference)

OpenAI API 的 compaction 将先前状态压缩为下一次请求可接续的窗口，包括模型专用的不透明压缩项；返回的窗口应按协议使用，不能自行删减。此为 OpenAI API 能力，不能假定 GLM/DeepSeek 的文本摘要具有同等效果。[官方压缩说明](https://developers.openai.com/api/docs/guides/compaction)

本插件借鉴预算、连续性和按需信息的原则，但用显式项目状态与来源保护授权，不让模型摘要成为项目批准的权威。

开源实现的组合参考：OpenHands 的 append-only 事件流与只读 View/Condenser；Letta 的 core/recall/archival 分层；LangGraph 的结构化 checkpoint；Aider 的预算内相关性映射；Beads 的持久任务图；Goose/SWE-agent 的旧工具输出治理。没有直接引入这些运行时依赖，只复用经过本插件状态与权限边界调整后的机制。

## 三层信息

| 层级 | 内容 | 保留方式 |
| --- | --- | --- |
| 决策信息 | 用户原话及来源、revision/epoch/generation、审核角色、依赖与指纹、返工原因和标准、活动任务、未解阻塞 | 当前简报逐字保留；超过预算仍保留并报告 |
| 工作简报 | 当前计划、最新关联执行、失败/中断/运行任务、成员实际状态 | 确定性投影，不交给模型猜测相关性 |
| 完整证据 | 旧检查点、完整验收报告、已结束历史、交付记录 | 原存储不改动；按引用分页读取 |

不能仅按“最近 N 条”保留用户指令。working 模式为每条用户消息建立有序索引；短回复、选择、约束和最近消息保留全文，旧长消息保留开头、长度、内容哈希和稳定来源引用。私聊指令标注原来源和适用范围待核对，不当成当前项目的新批准。尚未建立可验证的指令替代关系前，不使用模型摘要自动宣布旧约束失效。

现有权威仍是生命周期工具及权限控制。上下文中的用户消息、历史摘要或 evidenceRef 都不绕过实际操作校验。

## 当前已实现：工作简报与证据检索

默认 `team_project_status` 使用 `working`。保留兼容的 `current` 和完整 `full` 查询。界面看板与原始状态不变。

- 不再默认带已结束且未关联当前工作的一般历史执行；最新修复、复测以及所有运行、排队、失败、中断任务保留。
- 证据正文替换为 `team_context_read` 引用。引用包含项目、生命周期 revision、section/key、内容 SHA256。
- 读取既检查项目作用域，也检查 revision 与内容哈希。任一变化返回显式错误，调用方必须重新取引用；不以旧缓存冒充新证据。
- 默认每页 8,000 字符，最大 12,000；返回 offset/nextOffset/complete/totalChars。分页可精确重组原 JSON，分页并非摘要或静默截断。
- 返工 reason/criteria、检查点 blockers/remaining 原样保留。原始消息读取失败明确报错，不能推断没有约束。
- 简报超过 32,000 字符只标记 overTarget；这是字符预警，不伪称准确 token，也不强行切掉必要字段。

全局私聊索引会随消息数量增长，但旧长正文不再全部注入。后续只有在引入含来源、明确作用域、替代关系和独立验证的约束记录后，才把 recorded 事件投影成 active/superseded/revoked 生效集。

当前补充了确定性的用户消息 View：无 requestId 的相同正文仍是两个独立事件并保留原顺序；只有 requestId 和正文同时相同才折叠为重放，相同 requestId 对应不同正文会明确失败。每条消息均进入工作索引，“D吧”“同意”“通过”等短选择还会附带前一条角色回复的有界上下文。全文由 `team_context_history_read` 按固定消息数和内容哈希分页读取，新消息不会使旧快照失效。这里把历史记录标为 recorded，不自动断言仍然有效；真正的授权和项目状态继续由结构化工具决定。

项目群不会在每一轮重复注入幕僚长私聊的全部正文。群内保留最多 48 条带时间、requestId、长度、内容哈希和来源引用的跨作用域目录；优先保留最近记录、约束表达和短回复上下文，其他记录以数量、时间范围和聚合哈希注明仍在完整来源中。当前问题若引用旧决定，系统会同时检索本群和幕僚长私聊，把最多六条匹配的用户原话放到当前消息附近，并为两个作用域各保留最多三个优先位置。该证据用于恢复上下文，不能自动扩大授权；完整来源仍可按稳定引用分页核验。

## 当前已实现：调用观测

从原生事件只提取数值、模型标识、时间与封闭错误类型，不保存提示词、原始错误正文、工具参数或内部推理。

- 按角色、原生会话、turn/step 去重；每个逻辑步骤展示每次请求尝试。
- 区分首内容等待、步骤耗时、工具耗时、超时/传输/服务重试。
- token 缺失为未知；输入为提供方已报告字段合计并记录字段覆盖，缓存独立列示，不当成真实账单。
- 重复采样覆盖同一会话，不重复累加；原生会话恢复后可重建指标。
- 工作详情展示 P50/P95、重试与逐次明细。角色使用不同模型，聚合仅描述已采样调用，不用于能力排名。
- 查询最近更新 200 个已采样会话、每会话最多 1,000 步，界面展示最近 100 步。范围明确，不声称全量历史；等待时长截至采样时间。

## 原生压缩：当前运行边界

DSH Desktop 0.8.2 随附 `dsh-compaction-basic`。当前 profile 已启用该插件；未显式配置时其 `auto` 默认开启，阈值为上下文窗口 80%，近期保留为窗口 16%。它同时承担压力压缩和提供方确认的上下文溢出恢复，不能在没有替代兜底时直接关闭。

旧大会话并未因新简报上线而自动变短。宿主维护入口现在只允许认证 Codex 在成员空闲时触发一次原生压缩，并执行以下保护：

- 压缩前拒绝未配对、孤立或重复的工具事件。
- 对目标会话、全部活动项目、项目 revision、任务、用户指令、交接请求、幕僚长私聊索引、归档索引和当前模型生成决策清单；任一权威读取错误即拒绝。
- 使用 DSH 原生 `compactNow`，不手写 session JSON；原始 append-only 日志仍保留。
- 维护请求必须带稳定 requestId，并持久记录 started/completed/failed/committed_validation_failed；并发同键同参数共享一次执行，同键不同参数拒绝，账本损坏时关闭维护，不盲目重压。
- 可指定 conversationId 和 sessionId，按真实 `(conversationId, botId, workspace)` 会话执行；同一作用域存在多个 workspace 会话时必须指定 sessionId，不再固定为角色私聊。

DSH 的自动压力/溢出压缩已经存在。插件不能在提交前替换其内部事务，但现在每次模型请求都会从外部权威存储重新组装 `grokbot:authority-context`；自动压缩只能遮蔽旧会话表层，不能遮蔽该次新组装的项目状态和用户指令索引。任一权威读取失败会在 system prompt 组装阶段关闭本轮执行，因此不会继续进入自动压缩或模型调用。所有原生 compaction start/summary/end 只记录元数据到维护日志，不保存摘要、提示词或工具正文，并在角色工作详情中展示。

后续自动阈值演进仍须满足：

1. 只在原生执行器允许的边界使用原生 `compactNow`/维护机制，不手改 session JSON、不更换 sessionId 丢弃历史，不截断在途工具。
2. 压缩前记录原会话、表层版本与原始日志引用；确保最新操作回执、当前用户消息和未配对工具得到保留。
3. 压缩摘要是非权威交接材料。下一回合重新装载上述决策信息，逐项比较授权、revision/generation、当前任务、阻塞与验收要求。任何缺失或冲突不能继续变更操作。
4. 区分总输入预算与上次压缩后的新增量，避免固定指令较大时每轮反复压缩。一次失败不立即重试整个压缩循环；保留原上下文并报告状态。
5. 先在隔离会话比较长上下文与压缩结果的决策正确性，再按角色设阈值。16–32k 协调工作集、48–64k 开发诊断阈值、64–96k QA 诊断阈值均是待对照的初始目标，不是承诺或任务停止线。

此阶段未关闭 DSH 的上下文溢出恢复，也未宣称文本摘要能保证语义无损。安全性来自每轮重新注入外部权威投影、原始日志保留和结构化校验，不来自摘要自身。

## 重试与事件去重的边界

逻辑事件、请求尝试和执行副作用必须分开记录。后续同一事件重试只应复用未消费事件；不能靠比较自然语言相似度判断“已经处理”。有新版本或新用户消息时必须重新构建简报。压缩后的历史不可见时，不能引用一个已不在工作窗口中的旧快照而不补足内容。

现有重试策略暂不改变。事件去重与原生压缩是需独立测试的后续接入，不以减小提示词为理由省略幂等或重放验证。

## 验收与发布

自动测试覆盖长约束保留、失败读取、原始状态不变、当前版本与最新关联任务保留、跨版本读取拒绝、完整证据分页重组、指标去重、未知 token、请求重试、重启后指标读取与组件显示。

离线生产看板采样：原 current 投影 32,498 字符，working 投影 18,827；返工标准与 stepGenerations 逐项一致。这是该样本的看板体积变化，不是完整模型请求的 token 减幅，也不是响应提速证明。真实会话还需分别测量幕僚长私聊、项目群和成员会话；任一条会话的结果都不能外推到其他作用域。

不因发布本插件中断正常业务执行。部署后需验证新工具可用、指标能持久化、工作简报引用可读取；长短上下文模型对照与旧会话压缩另行验收。保留回退构建，不覆盖原项目状态和历史。
