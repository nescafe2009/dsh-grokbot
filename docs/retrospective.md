# 项目复盘与团队成长

复盘由幕僚长主持，用户在私聊或项目群说「复盘这个项目」即可。多个项目含糊时确认项目，已归档项目仍可复盘。不自动改变生命周期、验收结果或启动新派工。

## 证据与成绩单

先冻结当前计划、生命周期、任务交付、检查点和项目群对话作为证据快照；记录职责模板版本和自定义职责。模型给出判断，系统验证证据引用、角色归属、覆盖率与版本。当前最多纳入最近500项派工和300条群消息，完整阶段与生命周期历史；截断情况显示在报告中。未关联到项目的私聊内容不推定属于该项目。成员自述保留为待核实材料，不作为自动验收。

幕僚长评价目标与任务拆解、协作与风险处理、验收与反馈闭环。专业成员评价专业交付质量、验证与风险意识、协作与交接，并结合架构、开发、测试等当前职责判断。每维0–5分：3为达标，4为主动识别并解决风险，5需要可验证、可复用的显著改进。0–2须说明明确缺口和影响。证据不足填null，不按0分算；全部维度有证据才等权换算100分。分数是幕僚长的可追溯判断，不是客观能力测量。诚实上报、主动发现缺陷、环境中断和需求变更不得笼统计为能力不足。

报告包含总体结论、逐角色评分依据和建议、做得好的实践、问题根因及最多6个改进实验。相同证据快照重复提交复用原报告；状态变更后必须重新读取再提交，历史报告保留。报告在对话中提供链接，也可在Computer的「复盘档案」及成员资料回看。发现旧报告不准确时应说明旧结论限制，以新证据生成后续复盘，而不是修改原始验收记录。

## 成长闭环

每个实验记录负责人、适用场景、改进做法、验证标准与来源证据。实践状态为待实践、已验证有效、验证未通过、已停用。当前角色匹配的最近5条待实践/有效实验会在后续回合动态注入为低优先级实践提醒；不能覆盖用户需求、基础职责、权限和验收边界。跨角色变更不注入旧角色实践。不重写基础角色提示语，停用也保留历史。

用户可说「复盘新项目，检查上次改进是否有效」。幕僚长须对照实验标准说明验证结论；系统要求引用另一个项目中该成员已验收的阶段，且验收晚于实验创建时间。有效实验每次奖励5成长经验，同一成员在同一个后续项目最多奖励一次。新评分、重复调用、重启和实验改写不重复奖励。同一实验验证结果不能重复登记；无效实验需在新复盘中修改做法后再尝试。

成长经验与既有任务经验分别记账，展示等级时相加，保持原有见习/熟练/资深/专家/大师门槛。评分高低不直接加减经验。历史奖励不因停用被抹除。用户可要求停用不适用建议。

## 实现与限制

`team_retrospective` 提供inspect/evidence/publish/verify/retire（先读索引，再按ID分批读取最多20项详情，避免大工程一次塞满模型上下文）；仅幕僚长可调用，写入需要当前用户对话，后台通知不得自行评分升级。GET `/retrospectives` 列表和 `/retrospectives/:id` 报告只读。状态存在运行目录`retrospectives/ledger.json`，原子写入并串行处理，读取缓存随文件变化失效。报告转义HTML并禁止脚本，常见凭据脱敏，运行数据不进入发布包。

这是有记录、可验证的工作方法改进机制，不是模型权重训练。验收记录只能证明阶段通过，改进的因果效果仍由幕僚长结合证据判断；系统不会声称自动证明经验必然有效。
